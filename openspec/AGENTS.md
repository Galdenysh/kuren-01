# OpenSpec

Один change за сессию. Не пиши модель целиком. Не заводи change на каждый чих.

## Когда заводить change

Перед `openspec new change` / `/opsx-propose` предложи развилку и жди выбора:

- **Без change** — опечатка, lint, комментарий, баг уже описанного поведения, мелкий фикс внутри текущего среза
- **Change** — новый срез, новый скоуп, новый контракт (core/ui, снимок), новое требование в живой спеке

## Документация

Если правка меняет то, что уже записано в `openspec/specs/**`, вложенных `AGENTS.md` или `openspec/config.yaml` — сначала предупреди, что дока разъедется. Дальше развилка: поправить доку вместе с кодом, сделать OpenSpec-дельту, или оставить drift (только после явного ок). Архив не трогать. `.cursor/rules` не источник правды: не копируй туда закон.

## Цикл

1. Propose — `proposal.md`, specs, `design.md`, черновик `tasks.md`
2. СТОП — пользователь ревьюит `proposal.md` и `design.md`
3. Apply / `tasks.md` — только после явного ок или `/opsx-apply` после ревью
4. TDD ядра — падающий тест, потом код
5. UI — только после зелёных тестов ядра
6. Готово — `npm run verify`. UI в браузере только если пользователь сам запустил Dev

Перед кодом: `npx openspec list` и `npx openspec status --change <name>`.

## Запрещено

- поднимать `vite` / `npm run dev` без явной просьбы в этом сообщении. Сервер — Run Task → Dev
- коммит и git remote, пока пользователь не попросил
- заводить OpenSpec change без развилки «правка без change vs change»
- выполнять `tasks.md` или писать код среза, пока пользователь не принял `proposal.md` и `design.md`
- объявлять «готово» без `npm run verify`
