# Design

## Context

См. proposal.md — Why. `xor-training-lab` в архиве. Публичный API `src/core/nn`: `Mlp`, `Trainer`, `XOR_DATASET`, `NetworkSnapshot`. `Trainer.trainStep` и `Trainer.forwardSnapshot` возвращают снимок; `probeSnapshot` пересчитывает активации выбранной пары битов, не меняя веса. `TrainingLab` сам создаёт `Trainer` (`Mlp.xorMlp(42)`, `XOR_DATASET`) и рисует только снимок. `src/core/agent` — README, кода нет.

Граница, которую этот срез не размывает: математика и решение агента в `src/core`, React только показывает лог и снимок.

## Goals / Non-Goals

**Goals:**

- Один цикл: цель → снимок → действие → инструмент → снова, пока не стоп.
- Правило читает loss и счётчик своих шагов. Инструменты знают только `forwardSnapshot` и `trainStep`.
- Лаборатория и агент делят один `Trainer`. Ручные «Шаг» и «Серия шагов» остаются.
- Тесты ядра в Vitest (node), без jsdom. UI после зелёных тестов.

**Non-Goals:**

- Доучить XOR до порога 0.5 силами агента. Это уже требование `nn-core` (порядка 8000 шагов). Здесь цель — порог loss и бюджет, а не новая гарантия классификации.
- Кнопка сброса, поле ввода порога, второй граф, слоты `SlotCard` (на экран не выведены).
- Языковая модель, tokenizer, transformer, внешний API, SDK агентов Cursor, worker, GPU.

## Decisions

1. **Ядро решает, UI рисует.**  
   `src/core/agent` не импортирует `react` и `src/ui`. `src/ui` не выбирает действие и не вызывает `backward`. Альтернатива «правило внутри `onClick`» отвергнута: цикл нельзя было бы проверить без браузера.

2. **Два инструмента поверх публичного индекса `src/core/nn`.**  
   `createTrainerTools(trainer)`:
   - `snapshot()` → `trainer.forwardSnapshot()` — loss по всем четырём точкам, веса не меняются;
   - `trainStep()` → `trainer.trainStep()`.  
   Импорт только из `src/core/nn` (`Trainer`, `NetworkSnapshot`), не из `tensor.ts`. Политика (`decideRule`) nn не импортирует: ей передают число loss и счётчик. Альтернатива «агент сам читает `mlp.w1`» отвергнута: это приватный учебный объект, не контракт для агента.

3. **Порядок одного `cycle`.**  
   Снимок, затем правило:
   - `loss <= maxLoss` → стоп `goal_reached`, `trainStep` не вызывать;
   - иначе если `trainCount >= maxSteps` → стоп `step_limit`, `trainStep` не вызывать;
   - иначе `trainStep` ровно один раз и `trainCount += 1`.  
   Цель проверяется раньше лимита: при нулевом бюджете и уже низком loss причина — цель. `run()` крутит `cycle`, пока действие не стоп. Счётчик считает только шаги этого агента. Ручной шаг лаборатории его не увеличивает и не обнуляет; следующий цикл просто увидит новый loss.

4. **Лог — plain data.**  
   Запись: индекс, `observedLoss` (снимок до действия), действие `train` | `stop`, `stopReason` или пусто, снимок для экрана. Для `train` снимок — ответ `trainStep` (веса уже новые). Для `stop` — снимок наблюдения. В логе нет `Tensor`.

5. **Один trainer на странице.**  
   `App` создаёт `new Trainer(Mlp.xorMlp(42), XOR_DATASET)` и агента с инструментами этого trainer. `TrainingLab` получает trainer снаружи и больше не конструирует второй. История loss живёт в UI: и ручные шаги, и `train` агента дописывают точку. Граф по-прежнему берёт `probeSnapshot` выбранной пары. Снимок `trainStep` для графа не подставлять: у него активации последней точки цикла `(1,1)`, и переключатель входа начнёт врать. На график и в подпись Loss идёт loss снимка — он общий на датасет.

6. **Экран не вызывает `run()` до упора.**  
   «Шаг агента» — один `cycle`. «Серия циклов (50)» — не больше 50 циклов и стоп раньше, если правило остановилось. Предел 50 такой же по порядку, как серия лаборатории, и не даёт главному потоку прогнать тысячи шагов. `run()` остаётся для тестов с крошечным бюджетом.

7. **Учебные константы цели, не доказательство сходимости.**  
   На экране цель `{ maxLoss: 0.2, maxSteps: 200 }`. У необученной сети выход около 0.5, MSE около 0.25, поэтому 0.2 — порог «ошибка ещё большая → Train», а 200 — чтобы лимит был виден за несколько серий. Попадание в 0.2 этот срез не обещает: XOR при пороге класса 0.5 по-прежнему проверяет тест `nn`. Тесты агента порог кривой не используют: `maxLoss: 1` (стоп целью до шага, веса те же) и `maxLoss: 0`, `maxSteps: 2` (ровно два `train` и стоп лимитом).

8. **Файлы.**  
   `src/core/agent/`: `types.ts` (цель, инструменты, лог), `policy.ts`, `tools.ts`, `loop.ts` (`RuleAgent.cycle` / `run`), `index.ts`, `agent.test.ts`. README слота — русский учебный текст про цикл. UI: `src/ui/lab/AgentPanel.tsx` и `AgentPanel.module.css`, сборка в `App` рядом с лабораторией. Идентификаторы английские, JSDoc и подписи русские. Новая папка `src/ui/agent` не нужна.

9. **Дока области вместе с кодом.**  
   `src/core/AGENTS.md`: тесты агента лежат в `src/core/agent/*.test.ts`; цикл этого среза — там же; запрет языковой модели и transformer остаётся. Корневой `AGENTS.md`, `openspec/AGENTS.md` и строка context в `openspec/config.yaml` называют активный change `xor-training-agent`. Запрет tasks «не включать агентный цикл в `xor-training-lab`» не трогать.

## Risks / Trade-offs

- [Серия или `run()` на большом бюджете заморозит вкладку] → UI вызывает только `cycle` и серию с потолком 50. Тесты не гоняют 8000 шагов.
- [Порог 0.2 за 200 шагов может не наступить, студент видит только лимит] → лог пишет причину стопа. Оба стопа покрыты тестами с порогами 1 и 0. Классификацию XOR не переносим в агента.
- [Два trainer, если лаборатория оставит свой `useState`] → единственное место конструктора — `App`. Проверка: шаг агента двигает loss на уже открытом графике.
- [Граф прыгнет на активации `(1,1)`] → после шага агента лаборатория заново вызывает `probeSnapshot` выбранного входа.
- [`src/core/AGENTS.md` запрещает агентный цикл, пока фразу не поправят] → правка доки в том же apply, до кода цикла, иначе срез противоречит закону области.

## Migration Plan

Сохранённых весов и API для внешних клиентов нет. Откат — убрать панель и `src/core/agent` (кроме README-заглушки); `src/core/nn` не меняется.

## Open Questions

Нет. Порог 0.2 и бюджет 200 — учебные константы экрана; смена числа не меняет спеку, если правило и потолок серии сохранены.
