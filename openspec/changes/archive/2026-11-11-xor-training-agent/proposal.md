# Proposal

## Why

XOR-сеть уже умеет один шаг обучения и снимок `{ loss, weights, activations }`, а слот `src/core/agent` пустой. Срез показывает учебный цикл «цель → снимок → действие → инструмент» поверх этого trainer, а не вторую модель.

## What Changes

- Правило-агент в `src/core/agent`: loss выше порога → один шаг Train; порог достигнут или кончился бюджет шагов → стоп. Решения принимает правило, не языковая модель.
- Инструменты зовут только публичный API `src/core/nn` (`trainStep`, снимок). В приватные поля тензора агент не лезет и математику XOR не меняет.
- UI рисует лог циклов и ту же лабораторию на одном `Trainer`. Стили — CSS modules. Подписи и учебные комментарии на русском, идентификаторы на английском.

Вне скоупа: GPT, transformer, tokenizer, внешний LLM API, агентный SDK Cursor, облако, GPU, новый вид сети, сохранение весов.

## Capabilities

### New Capabilities

- `training-agent`: цикл правило-агента, который ведёт уже существующий XOR-trainer и отдаёт лог шагов для экрана.

### Modified Capabilities

- Нет. Требования `nn-core` и `training-lab` не меняются: шаг и снимок те же, ручные кнопки лаборатории остаются.

## Impact

- Код: `src/core/agent` (сейчас README), тесты рядом; панель лога в `src/ui` на общем `Trainer` с лабораторией. Новых зависимостей нет.
- `src/core/AGENTS.md` всё ещё запрещает агентный цикл «в срезе XOR» и велит не трогать `src/core/agent`. На apply эту фразу правят вместе с кодом: цикл живёт в `src/core/agent`, языковая модель по-прежнему запрещена. Строку tasks в `openspec/config.yaml` про `xor-training-lab` не переписываем — она про архивный срез. Корневой `AGENTS.md` и `openspec/AGENTS.md` на apply называют активный change `xor-training-agent`.
